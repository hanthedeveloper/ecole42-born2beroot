Bölüm I · Proje Tanıtımı

Proje Nedir?

Born2beroot, grafik arayüz olmadan sıfırdan bir Linux sunucusu kurmayı öğretir. VirtualBox üzerinde Debian kurulumu, disk şifreleme, güvenlik duvarı, parola politikaları ve sistem izleme scripti bu projenin temel yapı taşlarıdır.

2+
Şifreli LVM Bölümü

LUKS ile şifrelenmiş mantıksal disk bölümleri. root, swap, home, var, srv, tmp, var-log.

4242
SSH Port

Standart 22 yerine 4242. Root girişi kapalı. UFW sadece bu portu açık tutar.

10dk
Monitoring Aralığı

monitoring.sh sistemi izler ve her 10 dakikada wall ile tüm terminallere yayınlar.

Neden Debian Seçtik?

  • Geniş topluluk desteği ve dokümantasyon
  • APT paket yöneticisi — basit, güvenilir
  • AppArmor varsayılan olarak entegre
  • Yeni başlayanlar için Rocky'den çok daha az karmaşık
  • Rocky: SELinux gerektirir, KDump yok ama daha karmaşık
  • Debian: Stable branch — test/unstable yasak
  • Her iki OS da projeyi karşılar, tercih önemli
Bölüm II · Karşılaştırmalar

Debian vs Rocky & Diğerleri

Debian

  • APT · deb paketleri
  • AppArmor (path-based MAC)
  • Geniş topluluk, kolay dokümantasyon
  • Yeni başlayanlar için ideal
VS

Rocky Linux

  • DNF · rpm paketleri
  • SELinux (label-based MAC)
  • Enterprise ortama yakın
  • Daha dik öğrenme eğrisi

AppArmor

  • Dosya yoluna göre kısıtlama
  • Profil-tabanlı, okunması kolay
  • Debian'da varsayılan gelir
VS

SELinux

  • Etiket-tabanlı zorunlu erişim kontrolü
  • Çok güçlü ama yapılandırması zor
  • RHEL / Rocky'de varsayılan

UFW

  • iptables üstünde basit arayüz
  • Debian/Ubuntu için tasarlandı
  • ufw allow 4242 kadar basit
VS

firewalld

  • Zone-tabanlı dinamik güvenlik duvarı
  • nftables / iptables backend
  • RHEL ekosistemi için standart

VirtualBox

  • x86 üzerinde çalışır (Intel/AMD)
  • Okul bilgisayarları için uygun
  • Port yönlendirme kolay
VS

UTM

  • Apple Silicon (M1/M2) için
  • ARM üzerinde x86 emülasyonu
  • VirtualBox M1'de çalışmaz
Bölüm III · Savunma Soruları

apt vs aptitude

apt

  • Düşük seviyeli CLI aracı
  • apt-get + apt-cache'in birleşimi
  • Çakışmaları çözmez, hata verir
  • Script ve otomasyon için ideal
  • Debian'da varsayılan gelir

aptitude

  • Üst seviye paket yöneticisi
  • Bağımlılık çakışmalarını akıllıca çözer
  • Hem TUI (metin arayüzü) hem CLI
  • Neden kaldırıldığını gösterir
  • Ayrıca kurulması gerekir

Savunmada Beklenen Cevap

S: apt ile aptitude arasındaki fark nedir?
apt daha düşük seviyeli ve scriptler için idealdir; bağımlılık çakışmalarını çözemez. aptitude ise daha akıllı bir çözüm motoru sunar, çakışma olduğunda birden fazla çözüm önerir. İkisi de libapt-pkg kütüphanesini kullanır fakat aptitude varsayılan gelmez, ayrıca kurulması gerekir.

AppArmor Nedir?

S: AppArmor neden çalışıyor olmalı?
AppArmor, Linux Zorunlu Erişim Kontrolü (MAC) sistemidir. Her programa hangi dosyalara, ağ bağlantılarına ve sistem çağrılarına erişebileceğini tanımlayan profiller uygular. Proje şartı: boot'ta çalışıyor olmalı → aa-status ile doğrulanır.
Bölüm IV · Disk Yapılandırması

LVM + LUKS Disk Yapısı

lsblk
sda 30.8G disk ├─sda1 500M /boot └─sda5 30.3G └─sda5_crypt 30.3G crypt ├─LVMGroup-root 10G / ├─LVMGroup-swap 2.3G [SWAP] ├─LVMGroup-home 5G /home ├─LVMGroup-var 3G /var ├─LVMGroup-srv 3G /srv ├─LVMGroup-tmp 3G /tmp └─LVMGroup-var--log 4G /var/log

Neden LVM?

  • Bölümleri çalışırken yeniden boyutlandır
  • Birden fazla diski tek grup olarak yönet
  • Snapshot desteği
  • Mantıksal ≠ fiziksel bölüm esnekliği

Neden LUKS?

  • Disk-level şifreleme (AES-256)
  • Boot'ta şifre istenir → güvenli
  • Fiziksel erişimde veri okunamaz
  • dm-crypt üzerine standart katman
S: /boot neden şifreli değil?
Bootloader (GRUB) şifreli diski okuyamaz. /boot ayrı, şifresiz ext2 bölümünde tutulur. Kernel ve initramfs buradan yüklenir, LUKS şifresi sonra girilir.
Bölüm V · Ağ Güvenliği

SSH & UFW Yapılandırması

SSH Konfigürasyonu

/etc/ssh/sshd_config
# Port değiştirildi: 22 → 4242 Port 4242 # Root ile SSH girişi kapalı PermitRootLogin no # Parola auth aktif (anahtar da olabilir) PasswordAuthentication yes
$ sudo systemctl restart ssh $ sudo systemctl status ssh ● ssh.service - OpenBSD Secure Shell Active: active (running)

UFW Güvenlik Duvarı

ufw status numbered
Status: active To Action From -- ------ ---- [ 1] 4242/tcp ALLOW Anywhere [ 2] 80/tcp ALLOW Anywhere (bonus) [ 3] 443/tcp ALLOW Anywhere (bonus)
  • Default: gelen tüm bağlantılar reddedilir
  • Sadece 4242 açık (zorunlu)
  • Boot'ta otomatik başlar
  • Port 22 kesinlikle kapalı
S: Host'tan VM'e nasıl bağlanırsın?
VirtualBox'ta port yönlendirme: Host 4242 → Guest 4242. Ardından: ssh -p 4242 kullaniciadi@127.0.0.1 Dosya aktarımı için: scp -P 4242 -r . kullaniciadi@127.0.0.1:~/

Sudo & Parola Politikası

Sudo Yapılandırması

/etc/sudoers.d/born2beroot
Defaults passwd_tries=3 # Maks 3 yanlış şifre denemesi Defaults badpass_message="..." # Özel hata mesajı Defaults log_input, log_output Defaults logfile="/var/log/sudo/sudo.log" # Tüm girdi/çıktı loglanır Defaults requiretty # TTY olmadan sudo çalışmaz Defaults secure_path="..." # PATH kısıtlandı

Parola Politikası

login.defs
  • MAX_DAYS: 30
  • MIN_DAYS: 2
  • WARN_AGE: 7
pam_pwquality
  • minlen=10
  • ucredit=-1 (büyük harf)
  • dcredit=-1 (rakam)
  • maxrepeat=3
  • difok=7
  • usercheck=1
  • enforce_for_root
S: chage -l kullanıcıadı çıktısı ne gösterir?
Son parola değişim tarihi, sonraki zorunlu değişim, uyarı günü. chage --maxdays 30 ile mevcut kullanıcılara uygulandı.

Crontab Yerine Systemd Timer

  • Boot'tan 1dk sonra ilk çalışma (OnBootSec=1min)
  • Sonraki çalışma: önceki bittikten 10dk sonra
  • OnUnitActiveSec=10min
  • systemctl ile start/stop/status takibi
  • journalctl ile loglama otomatik

Wall Fix — SSH Sorunu

  • wall-broadcast.service oluşturuldu
  • Boot'ta /dev/pts/* terminallerini açar
  • PAM + mesg_fix.sh hook eklendi
  • Her SSH girişinde terminal otomatik açılır
  • SSH oturumlarına artık wall ulaşır ✓
S: Crontab yerine neden systemd timer kullandınız?
Systemd timer daha entegre: journalctl ile loglar otomatik toplanır, servis bağımlılıkları tanımlanabilir, systemctl status ile anlık durum görülür. Crontab bu görünürlükten yoksundur.
Bölüm VIII · Bonus

WordPress Stack — Docker

Mimari: docker-compose ile 4 servis

MariaDB :3306 WordPress FPM :9000 lighttpd :80 Caddy :80/:443

Caddy reverse proxy olarak dışarıya açıktır. lighttpd dahili ağda, WordPress PHP-FPM olarak çalışır. MariaDB hiçbir porta açık değildir.

lighttpd.conf (FastCGI)
fastcgi.server = ( ".php" => (( "host" => "wordpress", "port" => 9000, "broken-scriptfilename" => "enable" )))
Caddyfile
localhost { reverse_proxy lighttpd:80 }
  • NGINX/Apache2 yok → proje şartı ✓
  • Caddy = ekstra servis seçimi ✓
  • UFW: 80 + 443 açıldı
S: Neden Docker kullandınız, doğrudan kurulum yerine?
Servisler birbirinden izole çalışır, silmek/güncellemek kolaydır, tek komutla (docker compose up -d) tüm stack ayağa kalkar. Servis çöktüğünde restart: unless-stopped otomatik yeniden başlatır.
Bölüm IX · Sık Sorulan Sorular

Söyleşi Soruları

S: sudo ile su arasındaki fark?
su tamamen başka kullanıcıya geçer (şifre lazım). sudo tek komutu o kullanıcı adına çalıştırır, log tutar, kural bazlı kısıtlanabilir.
S: Neden port 22 değil 4242?
Güvenlik: otomatik tarama botları önce 22'yi tarar. 4242, standart olmayan bir port seçimidir. Ayrıca proje şartıdır.
S: Hostname nasıl değiştirilir?
sudo hostnamectl set-hostname yeniisim ardından /etc/hosts güncellenir, reboot gerekir.
S: Yeni kullanıcı ekle ve gruba ekle?
sudo adduser ali42 → sudo usermod -aG user42 ali42 → groups ali42 ile doğrula.
S: Sudo loglarını nasıl görürsün?
sudo cat /var/log/sudo/sudo.log — her sudo komutu giriş ve çıktısıyla loglanır.
S: LVM'de yeni bir bölüm nasıl eklenir?
lvcreate -L 2G -n yenibölüm LVMGroup → mkfs.ext4 /dev/LVMGroup/yenibölüm → mount.
S: UFW kuralı nasıl silinir?
sudo ufw status numbered → kural numarasını bul → sudo ufw delete [numara]
S: Monitoring scripti ne zaman durur?
sudo systemctl stop monitoring.timer — timer durdurulur, mevcut çalışma tamamlanır.
